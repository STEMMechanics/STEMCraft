HOW TO USE THIS SHEET
---------------------
Write P in a box for PASS, F for FAIL, or S for SKIPPED. Leave untested
boxes empty. Record failures by test ID in the notes at the end.
Each checkbox represents one test scenario; check every expected result
before marking it passed. Tests that need an unavailable fixture may be
skipped, with the reason recorded.
Print in portrait using a monospace font at 10 pt; lines fit 76 columns.

Commands beginning with / run in Minecraft. Gradle commands run from the
repository folder. Replace <arena>, <root>, <world>, <source> and <copy>
with your actual IDs. Do not type the angle brackets.
Replace <menu> with an existing menu ID from /imenu list.

Use a test server and copies of its configs/worlds. For YAML edits, stop
the server, edit plugins/STEMCraft/<file>.yml, then start it again. Do not
edit the same file with setup commands at the same time.

Prepare valid arenas with a lobby separate from their playing area,
spectator locations, and capacity for at least two players. Configured
spawns/grids must cover maxplayers; the random modes are tested later.
WorldEdit is needed for geometry changes. Citizens is needed for STEMBot.
Load the normal resource pack when checking HUD icons.

C. COUNTDOWN, START POSITIONS AND HUD - TEST EVERY GAME
======================================================

Run the following procedure separately for every checkbox C01-C09.
For C01-C07, <root> is the command named in the test row.

1. Stop the arena, then set minplayers to 1 and countdown to 30:
     /<root> stop <arena>
     /<root> set <arena> minplayers 1
     /<root> set <arena> countdown 30
     /<root> set <arena> roundseconds 45
     /<root> enable <arena>
   Keep maxplayers at least 2 and provide enough configured spawns.
   Boat Race/TNT Run preparation is listed in their own rows instead.
2. B runs /<root> spectate <arena> while it is waiting, observes its HUD,
   then runs /<root> leave. A runs /<root> join <arena>.
3. A alone must trigger a countdown, remain in the lobby for its full
   duration, and be able to walk/look around. No game hazards or mounts
   should start during that countdown.
4. B joins with about 15 seconds remaining. B must also stay in the lobby
   and be able to walk/look around. A must not be moved early.
5. At zero, both players move to their correct starting positions and
   receive the correct equipment/mounts. No delayed lobby teleport pulls
   either player back. No duplicate mount or repeated spawn is created.
   Floor Shuffle and Volcano now have an additional 15-second delay on
   the floor. Check the 'Starts in' HUD, walk and look around, and confirm
   no colour challenge or eruption starts until that delay reaches zero.
   The round timer starts at its full 45 seconds after preparation.
6. For C01-C07, run /<root> info <arena> during play. Check world, status,
   player/spectator counts, capacities, timers, lobby/spectator locations,
   numbered spawns and the game-specific fields listed below. It should
   report information without validating temporarily altered game tiles.
7. For C01-C07, play until the round ends. Check the HUD in every state:
   waiting = joined/needed players; starting = countdown/player counts;
   running = details listed below/time; ending = winner or '-' and reset.
   Check gold headings, purple rotating bossbar, icons and spacing. No
   raw placeholders or MiniMessage tags should appear on screen.
8. For C01-C07, results remain visible for 20 seconds, then reset removes
   occupants, restores their inventories/game modes/locations and allows
   another round. For C08-C09, stop after checking the start transition;
   those games retain their own configured round/reset timing.

J. STEMBOT WORLD ROUTES AND ARRIVAL ACTIONS
==========================================

Use Citizens and an enabled STEMBot. Use a test world separate from the
world whose introduction is owned by FirstJoin. For first-visit tests,
use a player who has not previously received an introduction there,
or a new test world name; reconnecting does not clear the seen marker.

Merge these actions into the existing actions map in stembot.yml:
  qa-command: ['talk:COMMAND ROUTE', 'sleep:100', 'close']
  qa-first: ['talk:FIRST VISIT', 'sleep:100', 'close']
  qa-arrival: ['talk:ARRIVAL ROUTE', 'sleep:100', 'close']

Merge this entry into worlds, replacing the world name and coordinates:
  <bot-world>:
    command-action: qa-command
    first-time-action: qa-first
    always-action: qa-arrival
    always-action-spawn: [<x>, <y>, <z>, 90, 0]

The fixed coordinates are the bot's feet, on safe ground with clear
headroom, inside the border and in a loaded chunk. Keep that spot far
enough from the player to distinguish it from a near-player summon.
Restart after script edits. /stembot close dismisses a normal session.

    Do: Have a fresh test player arrive in the configured world.

    arrival scheduling before deciding whether an action is missing.

[ ] J03 - Same-world teleport does not trigger an arrival

    Pass: No new ARRIVAL ROUTE starts just because of that teleport.
